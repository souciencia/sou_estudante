# Database

Estrutura do banco de dados (Elasticsearch 8.17). Os mappings ficam em
`packages/api/internal/ingest/mappings/*.json` e são embutidos no binário do
seed; em caso de divergência, o mapping é a fonte da verdade.

## Índices

| Índice | Origem | Uso |
| :--- | :--- | :--- |
| `cursos` | `data/dados_cursos.json`, fornecido pela equipe de dados | Busca e detalhe de cursos |
| `ies` | `data/dados_ies.json` (JSON, um array), fornecido pela equipe de dados | Busca e detalhe de IES |
| `dicionario-cursos` | Termos únicos de `curso.no_curso.keyword` do índice `cursos` | Autocomplete de cursos |
| `dicionario-ies` | Termos únicos de `no_ies.keyword` do índice `ies` | Autocomplete de IES |

Os nomes dos índices são configuráveis por variável de ambiente
(`CURSOS_INDEX_NAME`, `IES_INDEX_NAME`, `CURSOS_DICT_INDEX_NAME`, `IES_DICT_INDEX_NAME`).
Esses valores são os **nomes base**: a API lê o alias `<base>-latest` e a
ingestão cria um índice concreto `<base>-<AAAA-MM-DD>`.

### Como os índices são criados

A ingestão é o job `cmd/seed` (container `se_bulk`, `--profile bulk`; código em
`packages/api/internal/ingest/seed`). Ela usa **troca atômica de índice**
(blue/green): os dados são indexados num índice novo datado
`<base>-<AAAA-MM-DD>` (ex.: `cursos-2026-10-20`, `ies-2026-10-20`) e, ao final,
o alias `<base>-latest` (`cursos-latest`/`ies-latest`) passa a apontar para ele,
apagando o índice anterior. Se a ingestão falhar, o alias continua no índice
antigo. Os dicionários seguem o mesmo fluxo, com índices
`dicionario-cursos-<AAAA-MM-DD>`/`dicionario-ies-<AAAA-MM-DD>` e aliases
`dicionario-cursos-latest`/`dicionario-ies-latest`.

### Configuração comum dos mappings

- `dynamic: strict`: campo que não está no mapping faz a indexação falhar. Há um
  teste (`mappings_test.go`) que confere se o mapping cobre as structs Go.
- 1 shard, 0 réplicas.
- Analisador `brazilian_search` (tokenizer `standard` + `lowercase` +
  `asciifolding`) para busca textual sem acento e sem diferenciar caixa.
- Normalizador `ascii_lower` (`lowercase` + `asciifolding`) usado nos campos
  `*.exato`, que permitem comparar nomes por igualdade exata ignorando caixa e
  acento (base do parâmetro `exact` da API).
- Campos `keyword` **diferenciam caixa**. Como a ingestão aplica
  `textcase.Title` aos textos (ver abaixo), filtros por esses campos devem usar
  a mesma caixa (ex.: `Bacharelado`).

### Normalização na ingestão

Os campos de texto de nome/rótulo passam por `textcase.Title`: caixa de título,
com `de`, `da`, `do`, `das`, `dos` e `e` em minúsculas fora do início
(`"CENTRO-OESTE"` → `"Centro-Oeste"`, `"DIREITO"` → `"Direito"`). Isso vale para
nomes de curso, grau, modalidade, nível, CINE, localização, `turno` e
`nome_municipio` das ofertas SISU e, na IES, para `no_ies`, `no_mantenedora`,
`no_categoria_administrativa`, `no_organizacao_academica`, os nomes de
localização (`no_regiao`, `no_uf`, `no_municipio`, `no_mesorregiao`,
`no_microrregiao`) e `no_bairro`. Códigos e siglas (`co_*`, `tp_*`, `sg_uf`,
`sg_ies`), `modalidade`/`grupo` do SISU e os campos de endereço da IES
(`ds_endereco`, `ds_numero_endereco`, `ds_complemento_endereco`, `nu_cep`) são
gravados como vêm da origem (os códigos numéricos, convertidos para `string`).

## Índice `cursos`

- `_id` do documento: o campo `sequencial` (ex.: `"1"`). É o id usado em
  `GET /cursos/{id}`.
- `instituicao` é desnormalizada: além de `co_ies`, recebe nome, sigla,
  categoria e organização vindos do índice/arquivo de IES.
- `curso.no_curso` e `instituicao.no_ies` são `text` (`brazilian_search`) com
  subcampos `keyword` e `exato`.
- `sisu.ofertas` é **`nested`**: consultas sobre seus campos precisam de
  `nested` query/agregação; uma consulta comum em `sisu.ofertas.*` não os enxerga.
- `dt_carga` é `date` e aceita `yyyy/MM/dd HH:mm:ss.SSS`, `yyyy-MM-dd HH:mm:ss`
  ou ISO.

## Índice `ies`

- `_id` do documento: o próprio `co_ies` (numérico na origem, gravado como
  `string`).
- `no_ies` é `text` (`brazilian_search`) com subcampos `keyword` e `exato`.
  Os demais campos são `keyword`, `integer`, `float` ou `boolean` (ver o mapping
  `ies.json`). A localização, a categoria e a organização são objetos aninhados.

## Índices de dicionário

Servem ao autocomplete (`GET /cursos/sugestoes` e `GET /ies/sugestoes`). Cada
documento tem um único campo (`no_curso` ou `no_ies`) com um termo único do
índice de origem.

- O campo é `search_as_you_type` (`brazilian_search`), com subcampo `exato`
  (`keyword` + `ascii_lower`).
- Não usam `dynamic: strict`.
- Seguem o mesmo fluxo de troca atômica dos índices de dados: são recriados
  num índice datado novo e o alias `<base>-latest` passa a apontar para ele.

## API keys do Elasticsearch

Geradas pelo `setup.sh` com privilégio mínimo, e guardadas no `.env`:

| Variável no `.env` | Variável no container | Quem usa | Privilégios |
| :--- | :--- | :--- | :--- |
| `ELASTICSEARCH_APIKEY` | `ES_APIKEY` | API (`se_api`) | somente leitura nos índices |
| `ELASTICSEARCH_BULK_APIKEY` | `ES_INGEST_APIKEY` | seed (`se_bulk`) | leitura e escrita, criar/apagar índice |

A API nunca recebe a chave de escrita. O superusuário `elastic` só é usado pelo
`setup.sh` e pelo healthcheck do Elasticsearch.
