# Deploy

Como publicar o **SoU_Estudante** em produção. O deploy de **código** é
automatizado pelo GitHub Actions; os **dados** e a **configuração inicial** são
manuais. Separei o que é feito uma única vez, o que é manual recorrente (dados)
e o que é automático.

> Ainda não validado de ponta a ponta em produção. Antes de confiar no
> `deploy.yml`, rode o `setup.sh --prod` uma vez na VM manualmente.

## Modelo de execução

O stack roda como um usuário **sem privilégios** usando **Podman rootless**,
com um único bootstrap usando `sudo`. O deploy diário **não usa sudo**: a chave
SSH do CI não concede root. Use o **mesmo nome de usuário** em todas as VMs
(ex.: `ireno.ricardo`) para não ter que trocar secrets depois.

## A. Configuração única no servidor (VM)

1. Criar o usuário de deploy (sem privilégios) e dar sudo a ele **apenas** para
   o bootstrap:

   ```bash
   # como root (ou via console da nuvem)
   useradd -m -s /bin/bash ireno.ricardo
   usermod -aG sudo ireno.ricardo
   ```

2. Copiar o repositório para a VM e rodar o bootstrap como root/sudo:

   ```bash
   sudo ./scripts/bootstrap-rootless.sh ireno.ricardo
   ```

   Ele instala podman + compose, configura subuid/subgid, aplica os sysctls
   (`vm.max_map_count` e `ip_unprivileged_port_start=0`) e habilita linger.
   É idempotente: pode rodar de novo sem efeito colateral.

3. Criar a pasta de deploy, o `.env` (a partir do `.env.example`) e enviar os
   dados, tudo de uma vez:
   - Defina `ELASTIC_PASSWORD`. Na **primeira** vez, qualquer senha; nas
     seguintes, **precisa bater com o volume do ES** já criado.
   - Ajuste `ES_JAVA_OPTS` conforme a RAM da VM (até metade da memória).
   - Insira os arquivos da ingestão de dados
       - `scp usuario@origem:./data/ ~/sou_estudante/data/`
   - Garanta que o **usuário de deploy** seja dono da pasta (o Podman rootless
     monta `./data` e precisa de permissão):
       - `chown -R ireno.ricardo:ireno.ricardo /home/ireno.ricardo/sou_estudante`

4. Ajustar o `Caddyfile`:
   - Trocar `45.159.173.16.nip.io` pelo domínio real.
   - Trocar `HASH_AQUI` pelo hash de senha
     (`podman run --rm -it docker.io/library/caddy:2 caddy hash-password`).

5. Liberar as portas 80/443 e apontar o registro A do domínio para o IP da VM:
   - Na **Serverspace** o firewall fica no painel da nuvem, não no SO. VPS sem
     grupo de firewall costuma vir com tudo aberto; se houver grupo, adicione
     80/tcp e 443/tcp (e 22/tcp para SSH).
   - Registro `A` do domínio → IP da VM.

## B. Segredos no GitHub (uma vez)

Em *Settings → Environments → production*, criar os secrets:

- `SSH_HOST`
- `SSH_USER` (`ireno.ricardo`, o usuário de deploy — não `root`)
- `SSH_PORT`
- `DEPLOY_PATH` (`/home/ireno.ricardo/sou_estudante`)
- `SSH_PRIVATE_KEY`
- `SSH_KNOWN_HOSTS`

## C. Seed (manual, só quando os dados mudam)

Rodar o seed depois do primeiro deploy - precisa do Elasticsearch no ar e da key `ES_INGEST_APIKEY` gravada no `.env` — ambos criados pelo `setup.sh --prod`.

```bash
cd /caminho/do/deploy
podman compose -f docker-compose.prod.yml --env-file .env --profile bulk run --rm --no-deps se_bulk
```

## D. Deploy de código (automático)

`git push` para a `main` (ou *Run workflow* manual). O `deploy.yml` executa, em ordem:

1. `lint` + `test` (bloqueiam o deploy se falharem).
2. `rsync` do código para a VM (preservando `.env`, `data/` e `.git/`).
3. Na VM: `setup.sh --prod` → sobe o Elasticsearch, gera as API keys dentro do container, constrói as imagens, sobe API/front/Caddy e verifica
   `/healthz`, `/readyz` e o front.

## Notas sobre rootless

- O Elasticsearch em produção roda **sem** `bootstrap.memory_lock` (rootless não
  concede `CAP_IPC_LOCK`); o `vm.max_map_count` é aplicado pelo bootstrap. Para
  um índice de leitura pequeno, o custo é desprezível.
- Para o Caddy bindar 80/443 sem root, é preciso **podman ≥ 4.4** (backend
  `pasta`) + o sysctl `net.ipv4.ip_unprivileged_port_start=0` (o bootstrap cuida
  do sysctl e avisa se a versão for antiga).
- O `loginctl enable-linger` faz os containers (`restart: unless-stopped`)
  voltarem sozinhos após reboot.
