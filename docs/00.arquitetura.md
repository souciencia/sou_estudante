# Arquitetura

Visão geral de como as partes se conectam. Detalhes: banco em

## Fluxo de uma requisição

```
navegador ──► front Next.js (se_front :3000)
                 │  rewrite /api/* (next.config.ts)
                 ▼
              API Go (se_api :8080)  ── somente leitura, ES_APIKEY ──►  Elasticsearch (se_es01 :9200)
                                                                          ▲
                                   seed Go (se_bulk, job) ── ES_INGEST_APIKEY ┘
                                        ▲
                                   data/*.json (montado em /data, somente leitura)
```

- O navegador fala só com o front. As chamadas à API usam o caminho `/api/...`,
  que o servidor Next.js reescreve para a API (sem CORS no uso normal).
- A API é **somente leitura**: não importa o código de ingestão (há um teste em
  `packages/api/cmd/api/deps_test.go`) e usa uma API key só de leitura.
- A escrita no Elasticsearch é feita apenas pelo job `se_bulk` (`cmd/seed`),
  executado sob demanda (`--profile bulk`), com uma API key de leitura/escrita.
- Todos os containers ficam na rede `data_net`.

## O seed (ingestão)

Código em `packages/api/internal/ingest/seed`. Para cada arquivo de origem:

1. Lê o JSON do caminho configurado (`CURSOS_JSON_FILE_PATH`, `IES_JSON_FILE_PATH`).
2. Se o índice **não existe ou está vazio**, cria-o com o mapping embutido e
   indexa os documentos em lote (workers e flush configuráveis); caso
   contrário pula, registrando "índice já possui dados".
3. Para cursos, cada registro é enriquecido com os dados da IES (nome, sigla,
   categoria, organização) e os textos passam por `textcase.Title`.
4. Constrói os índices de dicionário (autocomplete) a partir dos nomes únicos,
   se eles estiverem vazios.

Limitações (reingestão exige apagar o índice; falha no meio deixa índice
parcial): [analise-sonnet.md](analise-sonnet.md), seção 9.

## Configuração de endereços da API: `API_URL` e `NEXT_PUBLIC_API_URL`

| Variável | Quem lê | Quando | Efeito |
| :--- | :--- | :--- | :--- |
| `API_URL` | `next.config.ts` (servidor Next) | build (imagem de produção, `ARG`) e execução (dev) | Destino do rewrite `/api/*`. Padrão `http://se_api:8080` (rede do compose). |
| `NEXT_PUBLIC_API_URL` | `services/api/config.ts` (navegador) | build | Base das chamadas feitas pelo navegador. **Ausente** = `/api` (usa o proxy). Se definida, o navegador chama a API direto e depende do CORS dela. |

Deixe `NEXT_PUBLIC_API_URL` ausente para que dev e produção se comportem igual.
Modelo em `packages/front/.env.example`.

## Desenvolvimento x produção

| | Desenvolvimento (`docker-compose.yml`) | Produção (`docker-compose.prod.yml`) |
| :--- | :--- | :--- |
| API | `Dockerfile.dev`: Go com `air` (recarrega ao salvar), código montado por volume | `Dockerfile`: multi-stage, binário estático, usuário não-root |
| Front | `Dockerfile.dev`: `next dev`, código montado por volume, `WATCHPACK_POLLING` | `Dockerfile`: multi-stage, `output: standalone`, `node server.js` |
| Seed | `Dockerfile.seed`, `./data` montado em `/data` | idem, imagem `sou_estudante/seed` |
| Portas | ES `9200`, API `8080`, front `3000` publicados no host | ES e API em `127.0.0.1`; front em `3000` |
| Imagens | construídas localmente | nomeadas `sou_estudante/{api,front,seed}:${IMAGE_TAG:-latest}` |
| Projeto compose | sem `name:` | `name: sou_estudante` |

## Módulos do produto

O front organiza a navegação em 5 módulos, com tema de cor próprio (ver
[30.frontend.md](30.frontend.md#temas-por-módulo)): 1 Carta Náutica (`/cursos`),
2 Bússola (`/ingresso`), 3 Âncora (`/permanencia`), 4 Telescópio (`/ies`) e
5 Sextante (`/comparar`). Os rótulos vêm de `MODULE_META` em
`packages/front/src/lib/module.ts`. Hoje só `/cursos` e `/ies` têm busca
completa; `/ingresso`, `/permanencia` e `/comparar` ainda não têm conteúdo próprio.

## Acessibilidade

O UI segue WCAG 2.1 AA. A skill `accessibility` (`.opencode/skills/accessibility`)
reúne os requisitos e deve ser consultada ao escrever ou editar componentes.
