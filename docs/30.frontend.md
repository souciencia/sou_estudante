# Padrões do Frontend

Pacote `packages/front/`.

- Stack: Next.js (App Router) + Tailwind CSS v4 + Biome
- Tokens: `src/app/globals.css` (fonte única)
- Classes: `cn()` em `src/utils/cn.ts`

## Acessibilidade

O UI segue WCAG 2.1 AA. A skill `accessibility` (`.opencode/skills/accessibility`)
reúne os requisitos e deve ser consultada ao escrever ou editar componentes.


## Arquitetura de Componentes

### Compound Component
- Use em componentes expansíveis ou com estrutura interna complexa
- Subcomponentes ficam na pasta do pai, um arquivo cada (`<pai>-<parte>.tsx`), e não são exportados soltos
- `index.tsx` só monta o namespace com `Object.assign(Root, {...})` e reexporta os tipos de props
- O consumidor controla ordem, layout e elementos intermediários
- Estado compartilhado: React Context (ver *Context e validação*)
- Só variação visual (variante, tema, tom): sem Context, use Scoped-Variable (ver *Variantes sem Context*)

```tsx
export const Profile = Object.assign(ProfileRoot, {
  Header: ProfileHeader,
  Tabs: ProfileTabs,
  Tab: ProfileTab,
  TabPanel: ProfileTabPanel,
})
```

### Agnóstico + Wrappers
- **Agnóstico:** apresentação, layout e estado; nomes neutros (`Profile`, `SearchHeader`, `FiltersPanel`). Não confundir com o *Root* do compound (ver [glossário](01.component-composition.md#9-terminologia))
- **Wrapper:** conhecimento de domínio (hooks, mapeamentos, textos); consome o agnóstico (`ProfileCursos`, `SearchHeaderIes`)
- O agnóstico nunca importa hook/serviço de domínio (`useSearchCursos`, `useSearchIes`)
- Lógica comum sobe para o agnóstico **só quando dois wrappers já a usam de forma idêntica** (`useFilterPanel`, `buildFilterOptions`); nunca por antecipação (ver `01.component-composition.md`, seção 6)
- Wrappers que divergem só em configuração ficam finos (config + composição)
- O agnóstico recebe hook e textos do domínio por props obrigatórias (ex.: `SearchAutocomplete`: `useSuggestions`, `placeholder`, `searchLabel`, `listLabel`); o wrapper (`SearchAutocompleteCursos`) os fornece
- Estados de carregamento de perfil (spinner, 404, erro) vivem em `ProfileLoader`; cada `Profile<Domínio>Loader` só informa hook, textos e destino do link
- Componentes de lista usam generics (`SearchResults<TItem>`); o domínio entra por props (`renderItem`, `getItemKey`) e os wrappers (`SearchResultsCursos`, `SearchResultsIes`) ficam em `search-results/wrappers/`
- Páginas de busca recebem os blocos por slots (`LayoutSearchPage`: `searchHeader`, `filtersPanel`, `results`...)

```tsx
export const ProfileCursos = ({ curso, module = '1' }: ProfileCursosProps) => (
  <Profile module={module}>
    <Profile.Header title={title} subtitle={subtitle} />
    <Profile.Tabs defaultValue="overview">{/* ... */}</Profile.Tabs>
  </Profile>
)
```

### Estrutura de Diretórios
- Agrupada por domínio/responsabilidade em `src/components/`:

```txt
src/components/
├── ui/       # primitivos agnósticos (button, tag, typo, card, ...)
├── layout/   # moldura do site e de páginas (header, menu, hero, routes-bar, layout-search-page)
├── search/   # blocos de busca (+ wrappers por domínio)
├── profile/  # compound de perfil (+ wrappers por domínio)
└── enade/    # formas, selo, máscara
```

- Cada componente tem pasta própria (kebab-case); subcomponentes na mesma pasta
- Wrappers ficam em `<agnóstico>/wrappers/<wrapper>/`

```txt
profile/
├── index.tsx
├── profile-context.ts    # só se houver Context
├── profile-root.tsx
├── profile-header.tsx
└── wrappers/
    ├── profile-cursos/
    └── profile-ies/
```

- Nunca criar componente especializado fora do `wrappers/` do seu agnóstico
- Domínio não ocupa pasta própria na raiz de `components/`
- `index.tsx` só quando há namespace; componente de arquivo único é `<nome>.tsx` (ex.: `ui/typo.tsx`)

### Nomenclatura
- Pastas e arquivos: `kebab-case` (ver [Nomes de arquivo](#nomes-de-arquivo))
- Agnóstico: `PascalCase` (`SearchHeader`)
- Subcomponente: `<Pai>.<Parte>` (`Profile.Header`), arquivo `<pai>-<parte>.tsx`
- Wrapper: `<Agnóstico><Domínio>` (`ProfileCursos`, `ActiveFiltersIes`)
- Sufixos de domínio: `Cursos` e `Ies` (ex.: `FiltersPanelIes`, `SearchHeaderIes`). **Exceção registrada:** `ProfileIES`, `ProfileIESLoader` e seus tipos mantêm a sigla em maiúsculas; não replicar em wrappers novos. O tipo de domínio `IES` (`services/api/types.ts`) também é sigla
- Context: `<componente>-context.ts` com hook `use<X>Context`
- Tipos de props ficam no arquivo do subcomponente e são reexportados no `index.tsx`
- Identificadores (variáveis, funções, tipos) em inglês; termos de domínio em português são exceção (`curso`, `ies`, `enade`, `uf`, `turno`, `faixa`, `oferta`, `instituicao`)

### Context e validação
- Crie Context só para coordenar estado que CSS não propaga (ex.: aba ativa) ou valor lido em JS
- Todo subcomponente valida que está dentro do pai e lança erro descritivo

```ts
// profile-context.ts
export const ProfileTabsContext = createContext<ProfileTabsContextValue | null>(null)

export function useProfileTabsContext(subComponent: string) {
  const context = useContext(ProfileTabsContext)
  if (context === null) {
    throw new Error(`${subComponent} must be rendered inside <Profile.Tabs>.`)
  }
  return context
}
```

### Design system (página oculta)
- Página de teste visual e documentação de padrões: `/design-system`.
- Fica fora dos menus e é habilitada só em dev (`NODE_ENV=development`) ou com a
  flag `NEXT_PUBLIC_DESIGN_SYSTEM=1`; em produção responde 404 e nunca é indexada.
- Organizada por seções com índice lateral: tokens (cores, tipografia, espaçamento
  e formas), componentes base, composições e padrões.
- Cada componente tem uma **matriz de estados** (default, hover, disabled, loading,
  erro, tamanhos, variantes) — é o que mais ajuda a pegar bug visual.

### Ciclo de desenvolvimento
O ciclo geral está em [`00.guidelines.md`](00.guidelines.md). Para componente visual, entre o *Green* e o *Commit* entra um passo:
1. **Red:** teste de comportamento (RTL, por papel/`getByRole`) que falha
2. **Green:** implementação mínima
3. **Refactor**
4. **Design system:** componente reutilizável de `ui/`, `layout/`, `search/`, `profile/` ou `enade/` ganha uma entrada (matriz de estados) na seção correspondente de `/design-system`. Dispensa-se entrada só de wrappers triviais e loaders sem UI própria
5. **Commit**

### Nomes de arquivo
- Componentes e subcomponentes: `<pai>-<parte>.tsx` em `kebab-case`; arquivo único é `<nome>.tsx`
- Testes e stories ao lado do componente, com o **mesmo nome do arquivo**: `<nome>.test.tsx`, `<nome>.stories.tsx` (nunca `index.test.tsx` para componente que não é `index.tsx`)
- Lógica que não é componente usa o sufixo de papel em `kebab-case`: `<nome>.service.ts`, `<nome>-context.ts`, `use-<nome>.ts` (hooks), `<nome>.utils.ts` quando houver mais de um utilitário no mesmo contexto. Utilitário isolado pode ser só `<nome>.ts` (ex.: `cn.ts`, `uf.ts`)
- Preferir exports nomeados; `export default` só onde o framework exige (`page.tsx`, `layout.tsx`, `error.tsx`, `loading.tsx`, `not-found.tsx`, `global-error.tsx` e o `meta` das stories)

## Estilização

### Princípios
- Nenhum valor solto no componente: cor, tamanho, família, raio e movimento vêm de tokens
- Tema por módulo via Scoped-Variable (`data-module`)
- Classes sempre via `cn()`

### Tokens
- Declarados no `@theme` de `globals.css`; valores só lá, não replicar na documentação
- Categorias: cores, tipografia, formas, movimento (`--motion-*`, `--ease-*`)
- **Acento por módulo:** `--color-m{1..5}-accent` (identidade) e `--color-m{1..5}-deep` (legível em fundo claro: texto/borda forte)
- **Acento escopado:** `--color-accent`, `--color-accent-deep`, `--color-accent-fg`; sobrescritos por `[data-module]`
- **Texto:** `--color-fg` (principal) e `--color-fg-muted` (secundário)
- **Neutros:** `--color-muted`, `--color-site-background`, `--color-card-surface`, `--color-border-border-primary`
- **Sobre fundo escuro:** `--color-on-dark` (texto e véus brancos sobre navy: `text-on-dark`, `bg-on-dark/10`)
- **Feedback:** `--color-enade-{ok,warn,low}` (+ `-surface`), `--color-progress-bar-*`, `--color-error` / `--color-error-surface`
- **Informação:** `--color-info-{surface,border,deep}` (banner de localização, tag de curso)
- **Callout:** `--color-callout-{accent,surface,accent-deep}`, sobrescritos por `.callout[data-variant]`
- **Famílias:** `--font-sans` (corpo), `--font-display` (títulos), `--font-mono` (dados numéricos)
- **Escala:** a padrão do Tailwind (`text-xs` 12px, `text-sm` 14px, `text-base` 16px, `text-xl` 20px, `text-4xl` 36px) mais `--text-display` (título de página de módulo) e `--text-2xs` (10px)
- **Forma:** `--radius-card`, `--radius-callout`, `--radius-panel` (painéis e banners internos), `--radius-control` (botões e controles pequenos). Pílulas usam `rounded-full`
- Medidas de layout (gap, largura) são classes Tailwind no componente, não tokens

### Temas por módulo
- Componente recebe `module?: Module` e emite `data-module` no elemento raiz
- `[data-module="N"]` reatribui `--color-accent*` para toda a subárvore; descendentes herdam do ancestral mais próximo
- Consuma pelas utilities de acento (`bg-accent`, `text-accent-deep`, `border-accent`), sem cor fixa
- Transparência com `/NN` (`bg-accent/10`); não crie variáveis `-surface`/`-light` por módulo
- Context do módulo só para filhos que o leem em JS
- Tipos: `Module` em `src/lib/module.ts`; `EnadeLevel` e `parseEnadeLevel()` em `src/lib/enade.ts`

```css
[data-module="1"] {
  --color-accent: var(--color-m1-accent);
  --color-accent-deep: var(--color-m1-deep);
  --color-accent-fg: var(--color-m1-deep);
}
/* [data-module="2".."5"] idem */
```

### Variantes sem Context
- Root emite `data-variant`; regras CSS escopadas reatribuem tokens; subcomponentes só consomem
- Subcomponentes não sabem qual variante está ativa
- Context apenas se a variante precisar ser lida em JS

```tsx
// callout-root.tsx
<div role="note" data-variant={v} className={cn('callout bg-callout-surface', className)} />
```

```css
@theme {
  --color-callout-accent: var(--color-info);
  --color-callout-surface: var(--color-info-surface);
  --color-callout-accent-deep: var(--color-info-deep);
}

.callout[data-variant="gold"] {
  --color-callout-accent: var(--color-warn);
  --color-callout-surface: var(--color-warn-surface);
  --color-callout-accent-deep: var(--color-warn);
}

.callout[data-variant="module"] {
  --color-callout-accent: var(--color-accent);
  --color-callout-surface: var(--color-surface-lv2);
  --color-callout-accent-deep: var(--color-accent-deep);
}
```

### Convenções de classes
- `cn()` obrigatório em classes dinâmicas, condicionais ou recebidas; nunca template literal, `clsx` ou `classnames` direto
- `className` por último, para permitir override
- Variantes complexas: object flags
- Proibido `text-[...]` (exceto os dois `clamp(...)` fluidos de título em `app/page.tsx` e `hero.tsx`) e paleta crua (`text-gray-500`, `bg-blue-600`, `bg-white`, `text-white`); use os tokens (`bg-surface-lv2`, `text-on-dark`)
- Proibido `rounded-[Npx]`: use `rounded-card`, `rounded-panel`, `rounded-control` ou `rounded-full`
- Texto nunca abaixo de 12px (`text-xs`). Única exceção: `text-2xs` (10px), só para texto complementar e redundante (hoje, a fonte de dados dentro de `Tag`); não use em informação essencial nem reduza o contraste com `opacity-*` (precisa de 4,5:1)
- Template literal em `className` é barrado pelo Biome (`biome-plugins/no-template-classname.grit`, roda em `npm run lint` e no CI)
- Ilustrações SVG (`formas-enade/*`, `bussola-hero.tsx`) são exceção: cores de desenho podem ficar fixas no SVG. Cores de acento de módulo, porém, usam `fill-mN-accent`
- Tipografia e cor de texto:
  - corpo: `font-sans text-fg` (o `body` já aplica os dois, então só repita para sobrescrever)
  - texto secundário: `text-fg-muted`
  - títulos: `font-display`
- `cn()` registra `text-display` (tamanho próprio) e os raios próprios via `extendTailwindMerge`; sem isso `text-display` seria tratado como cor e descartado
- Novo token de tamanho de fonte ou de raio: registrar em `src/utils/cn.ts`

```tsx
<div className={cn('p-4 rounded-card', isActive && 'bg-accent/10', className)} />
```

### Tipografia
- Tamanho segue a função do texto na página, não o componente
- `Typo` (`src/components/ui/typo.tsx`): prop `s` mapeia para a escala; família e cor herdam do contêiner
- Props de `Typo`: `title` → `font-display`, `mute` → `text-fg-muted` (sem alterar o cursor), `accent` → `text-accent-deep`
- Tamanhos de `s`: `xs`, `sm`, `md`, `lg`, `xl`

### Acessibilidade
- Base: WCAG 2.1 AA. Consulte a skill `accessibility` (`.opencode/skills/accessibility`) antes de criar ou editar componentes de UI.
- Um único `<main>` por página; os blocos internos usam `<div>`/`<section>`
- Foco sempre visível com acento (`focus-visible:outline-accent-deep`), nunca remova o outline sem substituto de contraste ≥ 3:1
- Texto sobre `bg-accent` usa `text-accent-fg` / `text-accent-deep`
- `prefers-reduced-motion` zera animações e transições globalmente

### Como estender
- **Novo módulo:** tokens `--color-mN-accent` / `--color-mN-deep`, bloco `[data-module="N"]` e `MODULES` em `src/lib/module.ts`
- **Novo tom ou medida:** token na categoria certa de `globals.css`; evite variável de uso único quando `/NN` sobre `accent` resolve
- **Novo tamanho de fonte:** use a escala; token novo só se o papel for distinto (e registre em `cn.ts`)
